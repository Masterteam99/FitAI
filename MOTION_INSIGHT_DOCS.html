Cosa Fa Motion Insight

App fitness AI-driven che combina generazione di piani allenamento/nutrizione personalizzati con analisi video della tecnica dell'esercizio in tempo reale (post-acquisizione).

✨ Feature Principali

  • Piani AI: generazione streaming con Claude + template professionisti
  • Analisi v2 tripartita: biomeccanica 50% + vision AI 30% + confronto PT 20%
  • Tracking: sessioni, streak, achievement, progressi, mappa corporea squilibri
  • Admin hub: utenti, abbonamenti, statistiche, audit log, upload video PT
  • Pagamenti Stripe: free/premium + gating + checkout/portale/webhook
  • PWA: installabile da browser (mobile + desktop)
  • Sentry reale: osservabilità in produzione

Architettura Analisi v2

Spec autoritativa: ANALYSIS_SPEC.md
Fonte di verità runtime: src/services/analysis/weights.ts + codice

Flusso Utente

  1. Utente apre sessione → vede lista esercizi
  2. Click esercizio → mostra video PT di riferimento + descrizione + note tecniche
  3. Click "Inizia" → camera attivata
  4. Countdown 15s (preparazione)
  5. Registrazione 15-25s video (durata da Exercise.recordingDurationSeconds)
  6. Stop automatico → upload video → Supabase Storage
  7. Analisi parallela (L1/L2/L3): ~120s totali
  8. Report finale con score combinato 0–100

📊 I Tre Livelli (L1/L2/L3)

Livello Cosa Fa Peso Tempo Max
L1 — Biomeccanica MediaPipe traccia 33 punti → angoli articolari 3D → confronta con ExerciseBiomechanicalSpec per fase 50% <5s
L2 — Vision AI 8 frame utente → Claude Sonnet vision → valutazione qualitativa 30% ~30s
L3 — Confronto PT Frame utente vs video PT di riferimento (Exercise.videoUrl) → Claude vision multi-image 20% ~60s

⚙️ Schema Dati v2

Exercise:

  • recordingDurationSeconds — durata registrazione target (15-25s)
  • videoUrl — VIDEO_RIF_1 (video PT professionale per L3)
  • biomechanicalSpec — relazione a ExerciseBiomechanicalSpec

ExerciseBiomechanicalSpec:

  • movements[] — per articolazione (es. left_knee, right_elbow)
  • └ phases[] — per fase movimento (CONCENTRIC, ECCENTRIC, ISOMETRIC, TOP, BOTTOM, THROUGHOUT)
  • └ triggers[] — condizioni (BELOW_MIN, ABOVE_MAX, OUT_OF_RANGE) + severity (WARNING/ERROR/CRITICAL) + feedback + injuryRisk

AnalysisSession:

  • videoUrl — video utente caricato
  • l1Result, l2Result, l3Result — output Json di ciascun livello
  • finalReport — report sintetizzato da Claude Haiku
  • combinedScore — score finale 0–100

📈 Differenze v2 vs v1

  • ✅ Post-acquisizione: No feedback real-time durante esecuzione (silenziosa)
  • ✅ Schema gerarchico: Spec → Movement → Phase → Trigger (phase-aware)
  • ✅ L2 con vision: 8 frame reali (non solo numeri)
  • ✅ L3 implementato: Confronto utente vs PT video con 12 frame allineati
  • ✅ Pesi aggiornati: 50/30/20 (vs 34/33/33 v1)

🎯 Logica L1 (Biomeccanica)

MediaPipe Pose Landmarker fornisce 33 keypoint 3D. Per ogni frame:

  • Estrai angoli articolari (joint angle in gradi)
  • Determina fase movimento via state machine
  • Applica trigger per fase corrente da ExerciseBiomechanicalSpec
  • Accumula violazioni (WARNING=1pt, ERROR=2pt, CRITICAL=3pt)
  • Score = max(0, 100 − (totalWeight / totalFrames) × 10)

Stack Tecnologico

  • TypeScript 5 — full codebase
  • Tailwind CSS 4 — utility-first styling
  • Middleware: src/proxy.ts (Next.js 16 rinomina middleware.ts)

Backend & DB

  • Prisma 7.8 — ORM con driver adapter @prisma/adapter-pg
  • PostgreSQL — Supabase (eu-west-3, Paris)
  • Client Prisma: generato in src/generated/prisma/
  • Pooler: transaction pooler (6543) runtime, session pooler (5432) migrate

Auth & Sicurezza

  • NextAuth v5 beta.31 — JWT session, @auth/prisma-adapter
  • Credenziali: bcryptjs + hash password
  • OAuth: Google (attivo), Apple (predisposto)
  • Rate limiting: Upstash Redis (aiRatelimit 10/min, analysisRatelimit 5/h, generalRatelimit 100/min)

AI & Vision

  • Anthropic Claude SDK 0.91.1 — Sonnet 4.6 (piani, vision), Haiku 4.5 (sintesi)
